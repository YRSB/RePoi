# ADR-0028: 专区与首页板块共享面板 (ZoneBoardPane) 宿主隔离与渲染不变式架构

## 状态
已采纳 (Accepted) - 2026-11-22

## 上下文与问题陈述
在首页与专区详情页（`ZoneDetailScreen`）中，均需要渲染动态流、分享、相册、讨论帖、二手、产品以及 5 类实体（厂商、系列、作品、角色、人物）等 10 类内容板块。
此前，首页与专区详情各自维护了一套布局与卡片渲染逻辑，导致多处体验漂移：
1. **容器边界与边距侵入**：各板块组件内部混杂了 `Scaffold`、`TopAppBar`、`PullToRefreshBox` 等外层容器组件，难以在首页多级 Tab 和详情页沉浸式折叠顶栏间复用；
2. **滚动状态错乱**：切换板块时若重新构造 `LazyVerticalStaggeredGrid` 或 `LazyListState`，导致每次切 Tab 都引发抖动或重组性能损耗；
3. **弹层与筛选逻辑嵌套**：产品板块的高级筛选与级联弹层若放置在有内容的面板内，一旦搜索结果为空或加载失败，面板直接被占位图替换，导致筛选弹层无法再次呼出；
4. **占位与错误态骨架分散**：各板块各自复制一套错误卡片、空卡片与分页指示器。

## 候选方案评估
### 方案 A: 泛型抽象组件 + 宿主全权代理
- 优点：外层高度抽象，代码行数表面较少；
- 缺点：10 类板块的数据结构与交互差异极大，泛型会导致大量 `as` 类型强转与类型安全性丢失；产品筛选等复杂交互无法类型安全地表达。

### 方案 B: 严格宿主隔离的单一内容渲染入口 (ZoneBoardPane)
- 优点：
  - 职责单一：`ZoneBoardPane` 纯粹负责内容瀑布流渲染，不持有任何外层容器与业务单例；
  - 宿主通过 `contentPadding` 注入视口安全区，实现首页与详情页的零漂移复用；
  - 宿主持有统一的 `gridState`，板块切换无抖动；
  - 内部使用强类型 `when(board)` 分发，杜绝泛型强转；
  - 弹层提升至宿主常驻挂载，不受空态/错误态影响。
- 缺点：需要在宿主与面板间定义明确的意图传递（`ZoneBoardIntent`）与动作分发。

## 决策结论
采纳方案 B，沉淀 `ZoneBoardPane` 作为全站专区板块的唯一内容渲染基元，并固化以下渲染不变式：
1. **纯渲染契约**：禁止包裹 `Scaffold`、`TopAppBar`、`PullToRefreshBox`、`FAB` 或 `TabRow`；内容边距严格通过 `contentPadding` 注入；
2. **零业务单例依赖**：禁止注入仓储、数据源或 `LocalAppMessages`，所有交互经 `onIntent` 与 `itemActions` 传递；
3. **单一滚动容器**：内部只允许存在一个 `LazyVerticalStaggeredGrid`，滚动状态 `gridState` 由宿主生命周期持有并传入；
4. **稳定键与内容类型**：严格保留 `key` 与稳定的 `contentType`（如 `feed_action`, `album_feed`, `zone_post`, `zone_resale`, `hobby_grid`, `zone_entity_<type>`）；
5. **强类型分发**：以 `when(board)` 分派各板块，保证类型安全；
6. **弹层外置隔离**：高级筛选弹层（`ZoneBoardHobbySheets`）必须由宿主在四态外无条件组合，禁止内嵌于面板；
7. **骨架与占位归一**：空态、错误态与分页指示器统一收敛至 `BoardGridContainer`。

## 影响
- 首页与专区详情彻底消除内容渲染差异与行为漂移；
- 避免了嵌套滚动手势冲突与重组测量开销；
- 新增板块时只需在封闭分发内扩展对应分支，无需改动容器拓扑。
