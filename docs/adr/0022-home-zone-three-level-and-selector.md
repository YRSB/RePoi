# ADR-0022: 首页三级信息架构与专区切换器重构

## 状态
已采纳 (Accepted) - 2026-11-15

## 上下文与问题陈述

Hpoi 2.43 首页已演化为**三级信息架构**：

1. 首级：专区（全部 / 关注 / 已关注专区）；
2. 次级：专区子板块（动态 / 分享 / 讨论 / 产品 / 二手 / 商品 / 厂商 / 系列 / 作品 / 角色 / 人物 / 社群）；
3. 三级：板块自带的内容筛选（动态为 9 项单选 Chip；分享（`album`）/讨论为排序；产品为高级筛选；二手为出售/求购 + 成色）。

RePoi 现状与此存在结构性差距：

- 首页 `HomeFeedScreen` 是「专区分类栏（`PrimaryScrollableTabRow` + 尾部 `+` 锚点）→ 9 项动态筛选胶囊 → 单一动态瀑布流」两级结构，**没有子板块层**；
- 子板块只存在于 `ZoneDetailScreen`（服务端 `api/zone/info.tabs` 下发 + 各板块独立状态与分页），首页无法复用；
- 首页级状态是单一 `HomeFeedUiState`，切专区/筛选即清空重载，无法承载多板块并存；
- ADR-0020 确立的「专区分类栏纯化 + 尾部常驻锚点」方案，在三级目标下无法容纳子板块层，且专区数量增长后横滑触达成本高。

设计约束：

- Material 3 规定 **Tabs 最多两级**，第三级必须是筛选/排序类控件（Chip / Menu / SegmentedButton），三级 Tab 是明确反模式；
- 「商品（`shop_item`）」为 Hpoi 自营商城内容，RePoi **不做**（避免替官方商城导流）——产品决策，非技术限制；
- 「社群（`community`）」RePoi 无任何实现，不纳入。

## 候选方案评估

### 方案 A：复刻 2.43 的图标横条（54dp 图标 + 12sp 文案，选中 3dp 描边）
- 优点：视觉最接近原版，专区识别度高。
- 缺点：占 78dp 首屏高度；图标资源需回退兜底；与「一级不可为 Tab、三级结构需清晰」的设计约束冲突，仍需自绘选中态；专区多时横向滚动定位困难。

### 方案 B：纯文字横向 TabRow（沿用现状视觉）
- 优点：改动最小，现有 `PrimaryScrollableTabRow` 与数据流可复用。
- 缺点：专区几十个时横向滚动不可用；一级与二级形成两条 TabRow，M3 层级语义混乱，且二级会退化为「Tab 套 Tab」。

### 方案 C（选定）：顶栏专区切换器 + 二级 TabRow + 板块筛选
- 一级收敛为**顶栏标题「当前专区名 ▾」**，点击展开**纯文本底部抽屉**（紧凑屏）或**锚定下拉菜单**（≥840dp）；
- 二级使用 `PrimaryScrollableTabRow`（主内容目的地），承载服务端下发且客户端已实现的板块；
- 三级为各板块自带的筛选/排序层。
- 优点：首屏省一行；一级选择空间不再受横向视口限制；层级语义干净（只有一级 Tab）；纯文本列表实现成本与可访问性最佳。
- 缺点：与原版视觉差异大（有意偏离，本 ADR 记录）；抽屉内无专区图标，识别度下降；需要新增长列表选择交互（搜索等延后）。

## 决策结论

1. **一级：专区切换器**。顶栏标题 = 「当前专区名 + 展开箭头」，点击后紧凑屏弹 `ModalBottomSheet`（纯文本分组 Chip），≥840dp 用锚定 `DropdownMenu`。列表 = 快捷「全部 / 关注」+「我的专区」（已关注专区，按 `ZoneTabsSettings.sort` 排序）+ 尾部主/次按钮「浏览全部专区」（主）「首页设置」（次）。不提供「进入专区详情」入口，详情页仍由专区广场进入。
2. **二级：子板块 TabRow**。单区以 `api/zone/info` 的 `tabs[]` 为准，交 RePoi 已实现白名单（10 类）裁剪，保留服务端顺序；聚合态（全部/关注）使用客户端固定列表——全部 10 类，关注 7 类（隐藏讨论/产品/二手，理由见能力矩阵）。使用 `PrimaryScrollableTabRow`。
3. **三级：板块筛选层**。不做全局统一行：动态 9 项单选 Chip（文案与键值对齐 2.43，`all`→`allInfo`）；分享（`album`）排序 + 分类；讨论仅排序（原版无分类入口、接口无分类参数，见 [抓包报告附录 C](../research/aggregate-api-verification.md#附录-c讨论板块分类参数探测)）；产品排序 + 年份/月份 + 分类级联 + 高级筛选抽屉（关注聚合当前隐藏，`homeScope=follow` 需登录态复验）；二手出售/求购（`SegmentedButton`）+ 成色；实体 5 类暂无筛选。筛选条保留现有「随滚动自动收起、到顶强制显示」行为。
4. **内容复用**：三个层级的展示区复用专区详情已有实现，抽出共享 `ZoneBoardPane`（板块内容 + 筛选 + 分页状态）；`ZoneDetailScreen` 保留自身顶栏/关注按钮/发布入口并复用同一面板，消除两套实现的漂移。
5. **状态记忆**：一级 `feed_zone_tab_key`（已存在）、二级 `feed_zone_board`（新增，值 `{tabKey}|{type}`）、三级 `feed_sub_type`（已存在）；冷启动若上次为「关注」或不可用则回落「全部」；旧筛选值 `all` 兼容映射为 `allInfo`。
6. **不做**：商品板块（产品决策）、社群板块（无实现）；聚合态若某板块经抓包验证不可用，则该板块在该场景自动隐藏，不做假入口。
7. **废止**：ADR-0020 的「专区分类栏纯化 + 尾部常驻锚点」条款由本 ADR 取代；ADR-0020 的「讨论板提升至顶栏动作区」结论已被 Issue #192 决策取代（讨论板下线并整链移除）。

## 影响

- **积极影响**：
  - 首页具备与 2.43 对齐的三级信息架构，且首屏更紧、专区可达性随数量线性扩展；
  - 二级板块实现从专区详情复用到首页，长期只有一套内容/筛选/分页代码；
  - 完全满足 M3「Tabs ≤ 2 级、第三级非 Tab」的层级约束。
- **消极影响 / 迁移成本**：
  - 需要抽取 `ZoneDetailScreen`（81KB 单文件）中的板块内容与筛选逻辑，回归面大；
  - 数据层需放宽参数：讨论的专区过滤改用 `zoneNodeId`（String、单值）；二手 `zones` 由 `Long` 放宽为 `String`；实体 5 类由单 `nodeId` 改为 `zones`（支持逗号串并集）。**产品与实体一律不下发 `homeScope`**——非空 `homeScope` 会让服务端忽略 `zones`、退化为全站（抓包实测见报告 §2.2）；产品关注聚合保持隐藏，直至登录态复验 `homeScope=follow`；
  - 聚合态「空 zones 是否等于全站」已由抓包验证通过（[报告 §2.1](../research/aggregate-api-verification.md)）：实现按「省略 zone 参数 = 全站」上线，不可用板块由能力矩阵直接隐藏，不加运行时闸门；
  - 首页 ViewModel 测试曾因真实 DataStore IO 被 CI 隔离，本重构前已改为注入内存 DataStore 并解除隔离（见 `docs/testing.md` 登记表与 [docs/home-hierarchy.md](../home-hierarchy.md) §7.3）。
- **相关文档**：详细设计规格与逆向事实见 [docs/home-hierarchy.md](../home-hierarchy.md)；术语见 [GLOSSARY.md](../../GLOSSARY.md)。
